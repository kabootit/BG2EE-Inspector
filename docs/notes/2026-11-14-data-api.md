## Plan summary

Phase 3 proved what the walker reads. This part makes it usable: a versioned Lua API for other mods,
text in the message window, and JSON lines for tools outside the game, all carrying one record that
holds only fields a check has proven. A line-by-line code review during the work replaced the planned
hand-written TypeScript guard with Zod, then found that the three checks' text formats each had two
definitions, one in Lua and one in a parser, and moved every line onto JSON defined in one schema
file.

## Gotchas worth remembering

- **The game's log keeps at most 4084 characters of an `Infinity_Log` message**, and cuts the rest
  silently. The log cut every party-check sprite dump since Phase 3 (about 2032 of 2048 bytes); the
  old text parser hid it, and so did the first `parseLines`, until a cut line counted as broken.
  `A7XJSON.line` now refuses lines above 4000 characters and the dump goes in 512-byte lines.
- **Colors in the message window are `0xAABBGGRR`.** Written as `0xAARRGGBB`, the first run showed light
  blue as gold and red as blue.
- **A module whose global another module clears must refer to itself through a local.** The API clears
  `A7XWALK`, `A7XJSON` and the rest; the walker already used a local, the JSON writer did not, and its
  new `line` function failed inside the API until it did. The API's Lua test caught it.
- **`A7X.show("all")` printed nothing once, and the cause is unknown.** In the first Data API run it
  wrote no record and no message; in the second, in the same area, it printed all 12 creatures. The
  first run left nothing to diagnose it with, because the API did not log the message window's text.
  It does now, every list ends with a summary line, and one unreadable creature no longer stops the
  rest.
- **The check scripts and the API cannot share a session**: the API takes `A7X_native` private, which
  the check scripts read directly.
- **The same party sometimes reads the same ids in another session.** Broomhilda was `133695479` in
  both Data API sessions, as in the first two Phase 3 runs, while the last two Phase 3 runs read
  other ids for the same party. What decides it remains unknown, so the API still treats an id as
  naming a creature only within its session.
