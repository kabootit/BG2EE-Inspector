## Plan summary

The hook gate showed the interposed `glClear` runs on the main thread, with the engine's `lua_State`
set from the first call and Lua idle at every call. Phase 2 needed the rest of the game's Lua API to
register a table and to read arguments and push results, plus the `g_pBaldurChitin` global for
`Root`. Those were found in plan mode, from the arm64 slice and a reference build of stock `lapi.c`.
The entries are written by hand rather than generated: there is one build, and a test checks every
entry against it.

## Gotchas worth remembering

- **A 32-byte prefix is not a fingerprint.** `lua_tointegerx` and `lua_setfield` start with the same 32
  bytes (prologue and the inlined index check), and most functions share their first 16. The sites hash
  whole functions instead; the test shows pointing `lua_setfield` at `lua_tointegerx`'s offset is caught.
- **The linker removed the Lua functions nothing calls.** `lua_rawgetp` is missing, so counting function
  starts from a known function lands on the wrong one. Sizes match the reference build exactly for most
  functions, and size is what placed them.
- **`lua_pushcclosure` with no upvalues does not allocate**, so pushing the registrar before
  `lua_pcallk` cannot raise. Everything that can (creating the table, interning the names) runs inside
  the protected call.
- **The debug console works only in a loaded game**, takes no pasted text, and takes one line at a
  time. The first attempt at the manual test assumed otherwise. Loading a script from `override/` with
  `Infinity_DoFile` reduces typing to one short line.
- **`Infinity_Log` lines are not at the start of a log line.** The engine writes them inside its own
  format: `… INFO: LUA: A7XT 1 native table`. The library's own lines (stderr) are at the start.
- **Lua 5.2's `%x` refuses negative numbers.** Found by running the test script under stock 5.2.4
  before the game; an `i32` read of a negative value would have stopped the in-game run.
- **The registration survives loading a save and changing area.** It happens at the first frame, at
  the main menu, and the same table answered after both, with no second registration.
- **The skill loader can serve an old copy of a skill.** The security-audit text loaded during this
  phase predated ADR-0005; the file on disk was current, and the audit followed the file.

## Verification

Run on 2026-11-06:

- **`deno task lint`**: fmt, lint, type-check, 80 tests (80 passed), `lint:docs` (40 files) and
  `lint:security` with no findings, on each of the six commits on its own.
- **`test/re/builds_test.ts` against the installed binary:** the slice's `LC_UUID` matches, `__TEXT`
  maps file offset 0 to `0x100000000`, and all 13 sites hash as recorded; checked separately that the
  test really read the 18 MB binary and reports a swapped offset.
- **`deno task build`**: arm64, ad-hoc signed; `otool -l` shows one 16-byte `__interpose` section.
- **A scratch C harness** that includes `native/a7x.c`, with the game's Lua API replaced by fakes:
  - the site check, on the real arm64 slice mapped from disk, passes, and fails naming the site for a
    flipped byte in `lua_setfield` and in the `g_pBaldurChitin` anchor;
  - every `Read` kind including sign extension, `cstr` (short, unterminated, at an unmapped page),
    `ReadBlock` bounds, bad addresses and kinds, `Version` and `Root`;
  - registration: waits while Lua is busy, registers when idle, does nothing for the same state,
    registers again for a new one, disables and pops the error when `lua_pcallk` fails, and disables
    on an unreadable `ci`.
- **The hardened-runtime stand-in**: `A7X disabled: unknown build`, and the same final OpenGL error code
  with and without the library.
- **`security-audit`**: no confirmed findings; the latent ones are under Follow-ups.
- **The [bridge manual test](../manual-tests/bridge.md)**, three attempts:
  1. Against `37cccc3`: incomplete. The console could not be used as written. The log already showed
     the build matched with 13 sites checked and `A7X_native` registered at 0.5 seconds.
  2. Against `37cccc3` with the revised test still uncommitted: incomplete. Run 1 of the script, after
     loading a save, passed every check; the party died before the area change.
  3. Against `20cfac2`, clean tree: passed. Session log of 1,052 lines, about 5 minutes. Every line
     below appeared in both script runs, run 1 after loading (19:01:32) and run 2 after the area change
     (19:04:00, after the engine's resource rescan at 19:03:34):

     | Check | Logged | Result |
     | --- | --- | --- |
     | Build and sites | `A7X build 2.7.3 arm64 matched, 13 sites checked, image at 0x104054000` | Pass |
     | Registration | `A7X registered A7X_native at 0.5s, glClear call 1`, once | Pass |
     | `native`, `version` | `table`; `1 2.7.3 arm64` | Pass |
     | `root`, `vtable` | `0x12b869e00`, `0x1047a10b8`, the same in both runs | Pass |
     | `cstr`, `block` | `string`; `0x40` | Pass |
     | `bad`, `badkind`, `badblock` | `nil` each | Pass |
     | `done` | `ok` | Pass |

     No `A7X disabled`, no `lua_State changed`, no `LUA ERROR`; the only `ERROR` lines are the
     baseline missing `dialogf.tlk` and music files. No home path in the log. No problems in play were
     reported. The script and `override/` were removed afterwards.
- **The vtable offset**, not a pass condition: `0x1047a10b8 - 0x104054000 = 0x74d0b8`, inside
  `__DATA_CONST,__const` as predicted, and the same offset in attempt 2 under a different ASLR slide
  (`0x1049050b8 - 0x1041b8000`). So `Root` very likely returns the `CBaldurChitin` object, whose first
  field is its vtable pointer.
